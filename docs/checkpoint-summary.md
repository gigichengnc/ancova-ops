# Historical checkpoint — v0.5.0

> **Historical note:** this document describes an early pre-ReasonedOps repository checkpoint. It is preserved for project history, not as the current project status.

At v0.5.0, the project was still developed under the name **ANCOVA Ops**. This was the first repository checkpoint where Phases 0–4 were presented as one coherent research/software system rather than as isolated implementation phases.

## Included at that checkpoint

- explainable service-request routing API;
- immutable routing audit history and human override capture;
- deterministic routing evaluation;
- executable synthetic-only data-governance controls;
- ANCOVA/regression diagnostics and adjusted comparisons;
- management-facing evidence reporting;
- offline adaptive-routing policy evaluation with approval and rollback controls;
- leakage-aware synthetic longitudinal recurrence benchmarking;
- Python 3.11/3.12 CI coverage across the major workflows.

## What changed after v0.5.0

Later releases added several important corrections that are not represented by this historical snapshot:

- case-type overlap and design-identifiability checks before adjusted department comparison;
- known-truth validity scenarios;
- the final evaluation applicability gate;
- explicit `use`, `caution`, `reject`, and `recommend_alternative` behaviour;
- the **Operate → Audit → Evaluate** project identity;
- the rename from ANCOVA Ops to **ReasonedOps**;
- the complete `reasoned_ops` package migration;
- a reviewer-facing rebuild narrative preserving the original Hackathon concept separately from current code.

## Evidence boundary at the checkpoint

Quantitative results at v0.5.0 were synthetic or hand-authored development evidence. The checkpoint did not contain representative real resident/customer pilot evidence and did not support production-performance or causal-improvement claims.
