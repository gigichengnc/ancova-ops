# Management outcome report

## Purpose

The Phase 2 management report translates the reproducible ANCOVA/regression workflow into a reviewable operational summary without hiding the statistical caveats.

It is deliberately a self-contained Markdown report rather than a deployed dashboard. Markdown can be versioned, reviewed in pull requests, attached to a meeting pack and tested in CI. A future web dashboard should consume the same structured report model rather than reimplement the statistics.

## Generate a report

Synthetic development data:

```bash
ancova-management-report
```

This writes the default report to:

```text
.ancova_ops/reports/management-report.md
```

Choose explicit Markdown and JSON outputs:

```bash
ancova-management-report \
  --synthetic-n 500 \
  --seed 2026 \
  --output .ancova_ops/reports/management-report.md \
  --json-output .ancova_ops/reports/management-report.json
```

Approved development CSV:

```bash
ancova-management-report \
  --csv path/to/development-data.csv \
  --output .ancova_ops/reports/management-report.md
```

CSV inputs must still pass the existing development governance boundary and contain an approved `data_provenance` value. The command does not bypass the synthetic-only policy.

## What the report shows

The management report includes:

- data provenance;
- total rows, complete cases and required-field exclusions;
- raw complete-case department means and medians;
- model-adjusted department mean resolution times with confidence intervals;
- a screening dashboard for missingness, residual variance, residual distribution, multicollinearity, homogeneity of slopes and influential observations;
- all warnings generated by the statistical workflow;
- the model formula and selected technical diagnostics;
- a non-causal interpretation boundary.

## Raw versus adjusted results

The two views answer different questions and must not be merged silently.

**Raw observed summaries** describe the resolution times present in the complete-case dataset. They can differ because departments receive different mixes of cases.

**Adjusted estimates** are model-based comparisons with the current covariates held at their complete-case sample means. They are useful for case-mix-aware investigation, but they are not causal effects and should not be treated as an automatic staff-performance league table.

## Screening status

The report uses two management-facing status values:

- `clear`: the current screening rule did not flag that issue;
- `caution`: the current screening rule identified a concern that should be reviewed before operational interpretation.

`clear` does **not** prove an assumption is true. It only means the current diagnostic did not cross its configured screening threshold.

## Current boundary

The report is an evidence-communication layer over the same Phase 2 analysis. It does not change the fitted model automatically when a diagnostic fails. Warnings remain visible so that a technical reviewer can decide whether robust inference, interactions, a different outcome distribution, hierarchical structure or a missing-data strategy is more appropriate.
